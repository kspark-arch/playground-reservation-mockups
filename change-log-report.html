초기 P0 프로토타입 구축 이후, 시연·검토 과정에서 반영한 주요 수정 사항과 그 결과(화면·정책·운영 흐름)를 공유용으로 정리한 자료입니다.

대상 시스템운동장 사용 예약 시스템 (로컬 시연용 P0)
실행 방식index.html 더블클릭 · 서버/설치 불필요
기술 구성HTML + CSS + Vanilla JS + localStorage
문서 용도내부 보고 · 시연 결과 공유 · 후속 개발 인수인계

1. 한눈에 보는 결과

  • 사용자: 예약 현황 확인 → 신청 → 내 예약에서 상태 확인·수정·취소 · 관리자 문의 · 이용 후기
  • 관리자: 알림 → 예약 관리(승인 대기·신청순) → 문의 관리 · 우선 배정 · 작업 이력
  • 핵심 정책: 승인 대기 중에도 시간대 선점, 1~8교시 시작, 최대 2시간, 전체/하프 동시선택 불가
  • 품질: 브라우저 자체 점검(tests.html)으로 주요 시나리오 자동 검증

2. 업무 흐름도

2.1 사용자 예약 신청 흐름

flowchart LR
  A[예약 현황] --> B{로그인?}
  B -->|아니오| C[로그인]
  C --> D[예약 신청]
  B -->|예| D
  D --> E[장소·일시·필수정보 입력]
  E --> F{정책/중복 검증}
  F -->|실패| E
  F -->|성공| G[승인 대기 등록]
  G --> H[해당 시간대 선점]
  H --> I[관리자 알림 생성]
  I --> J[내 예약에서 결과 확인]

flowchart LR

  C --> D[상세 보기]
  D --> E{검토}
  E -->|승인| F[승인 완료]
  E -->|반려| G[반려]
  F --> H[슬롯 유지]
  G --> I[슬롯 재개방]
  F --> J[신청자 안내문구 생성]
  G --> K[알림 처리완료]
  F --> K

  • 예약 신청·중복 차단
  • 본인 예약 수정·취소
  • 관리자 승인·반려·취소
  • 우선 배정(반복 차단)
  • 작업 이력(감사 로그)
  • localStorage 저장·초기화
  • 브라우저 자체 점검

4. 수정 이력 (요청 → 반영 → 결과)

시연·피드백 이후 반영한 주요 변경을 시간순에 가깝게 정리했습니다.

구분 수정 요청 / 이슈 반영 내용 결과
브랜드 한림대학교 표기 브랜드·문구를 연성대학교로 교체 시연 화면 전체가 연성대 기준으로 표시
정책 시간 단위·운영시간 정시 → 30분 단위(09:30~), 이후 1시간 슬롯·교시 표기 시작 1~8교시, 종료 최대 18:30(10교시)
신청 신청 정보 보강 신청자 이름·연락처 필수, 단체명 예시 안내 관리자가 연락 가능한 신청 정보 확인 가능
장소 장소 세분화 운동장/농구코트 × 전체/하프 4개소 장소별 예약·중복 검사 가능
장소 복수 선택 규칙 운동장+농구코트 동시 선택 허용, 동일시설 전체·하프 동시선택 금지 불필요한 중복 선택 차단, 시설 간 병행 예약 가능
정책 월 1회 제한 월간 예약 횟수 제한 제거 한 달에 여러 번 신청 가능
모바일 스마트폰 사용성 하단 빠른 메뉴, 반응형 레이아웃, 신청 화면 디자인 개선 모바일에서도 주요 기능 접근 용이
신청 입력 편의 장소 체크박스·필수항목 미입력 시 해당 위치로 이동/강조 신청 누락 항목을 바로 인지하고 수정 가능
문의 관리자 소통 사용자↔관리자 1:1 DM(문의/문의 관리) 예약 관련 질문을 시스템 안에서 처리
후기 이용 피드백 사용 완료 승인 예약에 별점·후기 작성/공개 이용 경험 공유 및 만족도 확인 가능
알림 승인 요청/결과 안내 신규·수정 신청 알림, 승인 문구 미리보기, 배지 카운트 관리자가 미처리 건을 빠르게 인지
알림 메뉴 역할 정리 알림 메뉴를 관리자 전용으로 이동 사용자 메뉴는 예약 중심, 관리자 메뉴는 운영 중심
관리 상세 검토 예약 상세 모달(신청자·연락처·장소·목적 등) 목록/알림에서 바로 검토 후 승인·반려
관리 처리 우선순위 예약 관리 목록: 승인 대기 우선 + 신청시간 오름차순 선착순 검토·승인에 맞는 운영 순서
현황 지난 날짜 표시 지난 날짜 슬롯 ‘예약 불가’, 달력 셀 회색 처리 과거/예약불가 일정을 시각적으로 구분
용어 감사 이력 명칭 화면 표기를 ‘작업 이력’으로 변경 운영자 관점의 용어로 통일
메뉴 상단 메뉴 혼선 사용자 메뉴 앞배치, 관리자 메뉴 뒤배치(+구분선) 역할별 메뉴 인지 용이
정책 선점 여부 확인 승인 대기(pending)도 점유 상태로 유지 신청만 해도 동일 시간대 중복 신청 차단

6. 시연·검증 결과

  • tests.html 브라우저 자동 점검으로 로그인·신청·문의·승인·우선배정·작업이력 등 핵심 시나리오 확인
  • 최근 점검 기준 주요 케이스 28개 통과 (환경에 따라 케이스 수는 기능 추가에 따라 증가)
  • 데이터는 브라우저 localStorage에 저장되며, 시작 화면에서 시연 데이터 초기화 가능
공유 시 참고: 본 시스템은 운영 서버가 아닌 로컬 시연용입니다. 실제 문자/카카오 발송, 다중 브라우저 데이터 공유, 보안 인증은 후속 운영 구축 범위입니다. 승인 안내 문구는 화면에서 생성·복사하는 시연 방식으로 동작합니다.

7. 권장 시연 순서 (보고용)

  1. 비로그인으로 예약 현황과 지난 날짜 회색/예약불가 표시 확인
  2. 학생(20260001 / 1234) 로그인 → 예약 신청(운동장+농구코트 가능, 전체·하프 불가)
  3. 운영자(operator / 1234) 로그인 → 알림·예약 관리에서 승인 대기·신청순 확인 후 승인
  4. 학생 계정에서 내 예약 상태 확인, 필요 시 문의/후기 확인
  5. 운영자 우선 배정·작업 이력으로 운영 기능 확인
